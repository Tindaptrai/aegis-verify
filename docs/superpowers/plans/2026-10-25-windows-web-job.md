# Single-Windows Web Job Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an authorized operator preview and approve one SCN-001 run on one explicitly provisioned paired Windows, then inspect its receipt, canonical Wazuh collection and evidence-backed evaluation.

**Architecture:** Extend the existing Django Job/DispatchLock and paired C# SCM agent with an explicitly versioned execution adapter. Immutable approval snapshots, reviewed target ownership and fresh local/worker/source readiness gate dispatch; an independent Windows supervisor journals one bounded process attempt and spools its receipt. The existing collector, canonical intake and evaluation engine remain the only path to detection conclusions.

**Tech Stack:** Existing Django/PostgreSQL, Python connector/engine, React/TypeScript/Vitest, .NET 10 with dependency-free test executables, native Windows Job Objects and PowerShell 5.1; no new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-25-windows-web-job-design.md` (owner-approved; no real-target handoff or lab run is authorized by local implementation). Read it with `docs/PRD.md` and `docs/ARCHITECTURE.md`.

**Issue / branch:** [#161](https://github.com/Tindaptrai/aegis-verify/issues/161), `codex/windows-web-job-single`. Reuse the current managed worktree; do not create a second checkout or broaden this issue.

## Global Constraints

- Scope is one paired Windows and one globally active job, provider `reviewed-scn001-windows/1`; Linux stays presence-only, Catalog ZIP publication never enables execution.
- Keep `paired_presence`, UUID/generation/certificate/environment, all v1 signed bytes/history, presence 2.0/network 2.1 DTOs and legacy unrelated dispatch unchanged.
- No ground-truth/pilot study edits, dependencies, hard-coded production addresses/connector URLs/secrets, checked-in certificates or unsanitized evidence. Test keys/certificates are generated into temporary directories.
- `aegis-windows-execution/2`, `manager-execution-v2`, separate RSA3072/PSS-SHA256 salt32 key; never reuse/rotate the v1 signing key, TLS CA or CurrentUser certificate.
- Request64KiB, envelope96KiB, decoded payload64KiB, depth12; presence remains 16KiB. Reject duplicate/unknown keys, NaN, noncanonical UUID/base64 and bool-as-int.
- Preview TTL120s; approve with at least30s remaining; timeout default300s, reviewed180..300s; collection≤900s; settle30s. UTC second precision only.
- Local readiness every15s, age≤30s; worker refresh≤10s including I/O, age≤30s; successful source probe age≤60s; measured clock uncertainty≤5s; idle poll5s; heartbeat15s.
- Windows10+/Server2016+, x64 PowerShell5.1, `-NoLogo -NoProfile -NonInteractive -File`; no ExecutionPolicy Bypass, EncodedCommand, shell/breakaway/WMI launch or uncontained fallback.
- Exact reviewed SCN-001 bytes only, kit0.3.0/scenario0.1.0; native/canonical local ASCII paths, no UNC/ADS/dot-segments/reserved names/reparse; path230/kit200/run206 limits; create-new output outside Git.
- SCM `AegisAgent`, `NT SERVICE\AegisAgent`, Automatic Delayed Start. Job Object is lifecycle containment, not a sandbox against the same service SID.
- `execution_receipt_is_detection_evidence:false`, `run_binding:unknown`, `collection_assurance:unknown`. Health/receipt/exit0 never create events, prove detection or declare completeness.
- Unknown source fields remain in raw evidence; absent canonical fields remain null. Security conclusions reference actual evidence IDs. Gap → Rule Fix → Re-test → Pass remains evidence-backed; this slice does not create the completeness declaration needed for false-negative conclusions.
- Use the existing focused worktree/branch, confirm its issue/acceptance criteria before product changes, and keep commits task-sized. Human/evidence review and separately authorized lab validation precede merge; no deployment, real ownership handoff or real rule installation is implied.

## Review Focus

- A delayed browser response after logout or permission loss must not reopen an actionable approval drawer (Task6).
- A previously cancelled/expired lease with an unknown terminal receipt must retain uncertainty and block reuse until review (Tasks2,4).
- Worker liveness during a slow source request must not mask stale/failed source health, or lose the durable collection claim (Task3).
- An upgrade interrupted between binary replacement and restart must preserve paired identity and pending journal, while never silently re-enabling execution (Task7).
- A JSON parser accepting duplicate keys, floats-as-integers or huge nesting must never create a cross-language signature/schema disagreement (Task1).

## File ownership and execution order

Task1 owns closed contracts and persistent records. Task2 owns transactional authorization/ownership and all execution routes; Task3 supplies its fail-closed readiness implementation. Task4 owns the paired Windows execution runtime. Task5 integrates the existing worker with immutable v2 collection inputs. Task6 owns the human UI. Task7 owns provisioning, packaging and enforced integration gates. Task1 must pass review first; Tasks2→3 and Tasks4→7 retain their interface dependencies. After Task1, frontend-only Task6 may run against the frozen public contracts alongside backend work; after Task3, Windows-only Task4 and Python-only Task5 may run concurrently. The controller serializes all staging/commits and generates each task's review range before another task commits. Each task still has its own reviewer gate, and final integration tests must exercise the real shared contracts. Early tasks use injected readiness/transport/native boundaries, but no partial build is advertised Ready.

Keep new Python execution files under `manager/control/` and C# execution files under `agent/connection/Aegis.Connection/Execution/`. Do not put parsing into validation, fork the engine, or route the paired runtime through legacy `Aegis.Agent --once`. Existing `agent/windows/Aegis.Agent/{Configuration,Protocol,Program,OwnedRunner,Native}.cs` are reference implementations; preserve their behavior unless a deliberately isolated shared extraction is covered by v1 regressions.
